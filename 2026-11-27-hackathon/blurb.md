# DeepSKA Group Hackathon

When: Friday Nov 27th, 2026. 10:00 - 17:00.
Where: Physics teaching lab, RHUL.

What:

A hands-on session focusing on developing software skills, aimed at highlighting software considerations beyond simply writing functional code.
We will work together to improve a piece of research code that was developed for solo use, but is now needs to be transitioned into a reliable and distributable piece of software.

In this session, we will be working collaboratively via GitHub to explore and practice the typical "development workflow" that (open-source) research software projects adhere to.
This will include:

- (re)Familiarising ourselves with how to contribute to a collaborative piece of software
- Learning how to interact with, and make best use of, issue tracking on GitHub.
- Practising making our own software contributions via pull-request, and both receiving and offering review.

In conjunction with the above; we will be looking at the importance of writing and adding tests to a software project, how to set up and maintain documentation pages for a software project, and how to separate out re-usable and distributable code from the "scripting" / "hard-coding" focus that research software typically ends up as.
By the end of the workshop, hopefully everyone involved will have had a chance to practice the aspects of the above that they are most interested in!

Pre-requisites:

- Must be familiar with the basics of `git`: adding, committing, and pushing/pulling/cloning to/from GitHub.
  Some familiarity with branches will be nice but is not required, as it will be recapped at the start of the session.
- Will need to be familiar with Python, being confident enough to read and understand other people's Python code.
- Please tell Vanessa:
  - Your GitHub account name / email.
  - If you already use an IDE to write code; EG VSCode, PyCharm, etc.
- Please come along having decided on your preference(s) between:
  - Practising the development workflow (contributing to other people's projects and/or providing review).
  - Writing and designing tests.
  - "Developer Ops": adding supporting infrastructure to a software project like documentation, automatic code formatting, and similar.
  - Organising and designing a codebase.
- **Please bring your laptop and a charger!**

Broad plan:

- 10:00 Welcome
- 10:10 Setup for the day; ensure everyone has repo access, has it downloaded and installed, knows how to branch and which branch we're working off. Figure out who's most interested in doing what.
- 10:30 Initial demo of the GitHub workflow (see the [setup notes](./setup.md) regarding this demo).
- 11:00 People work individually / in small pair-programming teams to tackle their first issues, which they can select from the list of open issues.
  RSEs on hand to provide support or suggestions for this.
  Participants open PRs when they're ready, and optionally review other people's PRs if they feel confident enough.
- LUNCH for an hour at some point between 12:00-14:00
- Afternoon: continues in the same vein as the above, hopefully with participants moving on to the "advanced" issues that the RSEs have pre-made, or tackling issues they have noticed during the workshop itself!
  RSEs on hand to answer any and all questions, and run demonstrations if there's something that would be good to show to everyone.
